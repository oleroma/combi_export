# Combi-Export Addon: Context & State Summary (handoff)

Blender 5.2+ extension (`combi_export/__init__.py`, single file) that batch-exports STL permutations by applying
user-defined overrides (node group → node → input → values/sweeps) across a hierarchy
Global → Preset → Collection → Object. Values can create sub-folders and filename tokens. README.md (user-facing)
and ARCHITECTURE.md (internals) are current, as is the in-addon EXTENSION GUIDE panel.

Repo: `D:\extensions\combi_export` (git). Check `git status` for uncommitted work. Core logic, migrations and the
headless worker are verified in background Blender 5.2.0 (probe scripts, 2026-10-09); the panels were only drawn
against a fake layout, not used interactively.

## 1. Core concept: branching & merging, for folders AND filename tokens

Values with a folder (`use_dir`/`dir_tag`) or a filename tag (`use_tag`/`tag`) create branches, e.g. letters
A B C × numbers 1 2 → folders `A/1 … C/2` or names `Box_A_1 … Box_C_2`. An override further down can be attached to
an existing branch instead of multiplying every permutation. Folders ("dir") and tokens ("tag") are two parallel
branches with identical rules:

- Block sub-folder / block tag `B` → only B permutations get the block's values: `B/1/X` or `Box_B_1_X`.
- `C/2` → only C2; `2` → every 2 branch. Several names separated by `/` (also for tags).
- New folders go below the branch's deepest folder; new tokens go at the end of the filename.
- A block with both a folder and a tag anchor only applies where BOTH match. Same for a value's dir + tag.

Rules per name (`_place_dir_parts(parts, branch, known, kind)`):
1. Name already in the branch (any ancestor folder / any earlier token) → merge. Several names must appear in order.
2. Name is a branch name (generated by an earlier value, every sweep step included) missing from this branch →
   override/value **inactive** for this branch.
3. Anything else → new folder / new token.
Matching is case-sensitive.
**Only typed value names anchor** (`value_name_parts` → `(anchors, names)`): a value's anchors (the names typed in its
field: replace `B`, folder `B\` / `C/2\`, tag `B_`) go through these rules; the value's own folder / token (blank
field, or after `B\` / `B_`) is always new. No append / prepend rules any more (removed 2026-10-10). Tag anchor `a_b`
is a chain split at `_` (`segment_tag`): `B_2_` merges into B then 2; tokens in the branch (else known) keep their `_`. Value names never anchor, so two inputs sharing a value (`1`, `True`)
multiply (`1/1`) instead of merging (bug found 2026-10-09: 3×3 gave 3 variants). They are still branch names that
blocks anchor to.

### Key functions
- `value_name_parts(val, field, kind)` (blank = value, `x` replace, folder `x\` = folder x then the value folder, tag
  `x_` = token x then the value token), `split_value_tag_parts` (keeps edge `_`), `segment_tag(s)`, `value_parts`,
  `value_field_anchors`, `value_branch_names`.
- `split_path_parts` (folders) / `split_tag_parts` (literal tag fields: `/` separates tokens, edge spaces and `_` stripped).
- `_known_branch_dirs(overrides)` – `("dir", name)` / `("tag", name)` keys known before each override (`id(ovr)`),
  each input (`(id(ovr), input_name)`) and the override's node group (`("group", id(ovr))`, via `MockOverride.group_uid`).
- `_place_block` – group block, then node block, each its own chain (node can merge into the group's names). The
  walker places the group block ONCE, before its first node, against names known before the group; its names join
  the branch with the first node that applies (2026-10-11: re-placing it per node made chain `Y/2`, Y new, drop every
  node after the first, and `Y/P` with P plain gave later nodes an extra `P` folder).
- `walk_override_branch(overrides, combo, known_before)` – **single source of truth**. Walks overrides top-to-bottom
  with `dir_branch` and `tag_branch`; returns `(active_input_ids, tags_by_level, paths_by_level)`.
- `generate_named_combinations` – recursion over `_build_override_pools`, keeps only variations the walker marks
  active; if no value of a pool applies the param stays default for that branch; leaf combos filtered + deduplicated.
  Yields `(combo, tags_by_level, paths_by_level)` from the leaf walk (no second naming walk).
  `generate_override_combinations` wraps it (combos only).
- Headless loop: before applying a variant, `revert_overrides(..., skip=override_targets(combo))` restores every socket
  the variant leaves out (otherwise the previous variant's value leaked into "default" branches).
- `format_export_filename(obj_name, obj_tag, col_use_tag, col_tag, tags_by_level)` → `Object` + `_token` for every
  token in hierarchy order: Global ovr → Preset ovr → Collection tag → Collection ovr → Object tag → Object ovr
  (`join_name_segments`: a collection/object tag collapses into an equal neighbour; equal override tokens stay).
  Example `Box_A_v2_1_lid.stl`.
  **Behaviour change:** collection/object tags are plain tokens now; the object tag no longer renames/prefixes the
  object name (user chose this). Old `_lid` style still works (edge `_` stripped).
- `build_export_dir_parts` – folders: GLOBAL ovr, preset prefix, PRESET ovr, collection sub_path, COLLECTION ovr,
  object sub_path, OBJECT ovr (`join_name_segments`: only fixed parts collapse into an equal neighbour).
- `get_override_signature` now includes block `ng_sub_path`/`node_sub_path`/`ng_tag`/`node_tag` (bug fix: objects
  differing only in block sub-folders were batched together in the headless worker and got the wrong folders).

## 2. Data model changes (this session)
- `BatchSTLValue`: `dir_tag` folder name, separate from `tag` (filename). Stored data only: the UI edits a value
  through one computed field, `expr` (section 7). New values are plain (`add_value`; the RNA `use_dir` default stays
  True for old data); `name_permutations` adds `@` (or copies the input's naming) once `+` / a sweep makes it permute.
- `BatchSTLNodeGroup` / `BatchSTLNode`: `tag` next to `sub_path`, edited through the computed `naming` field.
- `MockOverride` carries `ng_sub_path`, `node_sub_path`, `ng_tag`, `node_tag` (set in `get_flat_overrides`,
  kept by `resolve_overrides`). A block with only a sub-folder/tag and no inputs still becomes an override.
- JSON: values `dir_tag`; blocks `tag`. Old JSON without `dir_tag` gets `dir_tag = tag`. .blend data: scenes without
  a stored `batch_stl_data_version` are migrated on load/register (`migrate_scene_data`: empty `dir_tag` = `tag`);
  `_rebuild_ui_cache` stamps `DATA_VERSION` on the active scene so new scenes are never migrated.

## 3. Merge predictions in the UI (`BranchScope`)
- Entries `(kind, name)` → desc, `known` (exporter branch name), instances (`group`/`alt` = input/value or None for
  blocks, `reqs`, `needs` = reqs + name + alt, `pos` creation order, `base`). Context = name keys +
  `("alt", input, value)` keys + `("not", keys)` (the branch lacks at least one of `keys`) + `("any", rests)` (the
  branch has every key of at least one rest).
- `chain_states` (every placement, chain order via `pos`, branch names must merge), `segmentation` (tag split like
  the walker), `place(chains, ctx)` (folder + tag chains of one block / value jointly) → hits / dead / fresh names.
  `satisfiable(ctx)` = backtracking over value choices (three-way conflicts; step budget → yes), cached per `seq`;
  `not` keys are checked at the leaf against the solved keys closed over instances whose requirements are met.
  A plain name created anew adds `("not", reqs)` per instance it skipped, so `x_1/A` on path `A/x_1` is dead.
- (2026-10-11) A merge brings its instance's requirements (`_merged`), for plain block names too (before, a plain
  merge required nothing, so `Y/Y` merging into a Y made under I0=C was offered next to a tag needing I0=A). A plain
  name itself never enters a context: it exists wherever its requirements hold, and the search leaves out the names
  in a field's context. `place` returns `join(ways)`: the keys every way shares plus `("any", rests)` (before: the
  shared keys only, so a value inside node `B/B`, placed via I1=B or via I3=B, looked possible with I1=C and I3=C).
  Ways are capped at `MAX_WAYS` (64); after a cut, `join` keeps only the shared keys.
- Dead blocks / values: their value names stay `known` without instances (the walker still anchors to them). Sibling
  values of one input resolve against the scope before the input.
- Node group names (2026-10-11): `enter_block(ng)` records the group's fresh names wherever the group fits, so its
  nodes / values merge into them. `close_group()` then narrows each to one instance per context a node of the group
  applies in, keeping the group's `pos`. It runs at the next group's `enter_block` and at the end of `upstream_scope`'s
  `add_group`. This mirrors the walker, which adds a group's names with its first applying node. Verified 2026-10-10 by a randomized cross-check of
  predictions and suggestions against `walk_override_branch` (0 mismatches in 1,000 setups; 2 in 600 setups whose
  values contain `_`, from the walker's per-branch spelling of `a_b`).
- `upstream_scope(item)` → `(scope, ctx)` at any field via `item.path_from_id()` (`_PATH_STEP`). Export order:
  Global, Preset, Collection, Object lists; groups/nodes top to bottom; block sub-folder, then tag, then inputs.
- `naming_completions(scope, ctx, kind, text, current, other_parts, multi_part)` (the former `make_scope_search_cb`
  core): blocks multi-part (`@C/` completes `@C/1…`), value sections single. Completes only after a prefix that fully
  merges, in chain order, and only names the other section (folder vs tag) still fits with.
- `draw_overrides_table` builds the scope incrementally (cheap). Merging block → blue `batch_stl.merge_info` bar on
  top of its box ("Merges into C / 2 · name B"), field icon `AUTOMERGE_ON` (`ICONS['MERGE']`). Impossible merge →
  red "Never applies" bar. Value merge → merge icon on the info button before its field; dead → red. Tooltip lists
  sources.
- Collapsed table with inputs = clear view: only input/value rows (same walk, block rows skipped); the hidden
  blocks' merge bars become one merge_info icon at the input row start (red if dead, tooltips joined).
- `BATCH_STL_OT_merge_info`: INTERNAL no-op operator, `description()` returns the tooltip.

## 4. Other changes
- **Undo rule**: search fields (`search=`) get no automatic undo from Blender → each has a labelled
  `on_no_spaces_update(prop, label)` / `edit_callback` that pushes one step ("Edit Override Directory",
  "Edit Override Tag", "Edit Override Group/Node Sub-folder", "Edit Override Group/Node Tag"). Plain text fields get
  undo from Blender and must NOT push. Operators (`'UNDO'` + `@inside_operator`) suppress nested pushes.
- Values are edited through the `expr` search field (Blender's own clear button); `CLEAR_VALUE_STRING` is gone.
- **Group Output** is a valid node target, sorted after regular nodes (never the default). Group Input excluded.
- Removed the dummy `search_empty_cb`.

## 7. One field per value (2026-10-10)
- Request: replace the value / directory / tag fields of the overrides table with ONE field using symbols, keeping
  every variation and the merge predictions. Decision: `value @folder #tag` (`EXPR_SIGILS`), section text = the old
  field text (same `value_name_parts` rules), missing section = naming off. Sweeps in the value part: `start:step:count`,
  `{a, b}`, `*`. Quotes protect `@` / `#` (`""` = quote). Block rows got the same: `naming` = `@C/2 #B` (bare text is
  a folder).

  migration, JSON, signature or walker change. `set` validates and writes inside `raw_edits()`; `update` pushes the undo
